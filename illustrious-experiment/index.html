Existing implementation reference

Browser SDXL · ONNX WebGPU

A separate project already runs SDXL in Chrome with a JavaScript pipeline, OPFS caching, FP16 and INT4 UNet variants. Its inpainting example fuses a specific LoRA before export; it does not demonstrate arbitrary live LoRA swapping.

We can adapt its SDXL pipeline architecture, then validate the Personal Ami LoRA against Illustrious. This is a reference implementation, not a dependency.

    Browser-side LoRA format reference

    SDXL LoRA browser package

    The same publisher repacks a standard Kohya .safetensors LoRA into lora.json plus lora.bin for its browser runtime (FP16 factors; its example has 788 UNet layers). This is a custom format, not built-in ONNX Runtime support, and its layer map cannot be reused for Personal Ami.

    We'll need to map the actual Personal Ami tensors onto the Illustrious ONNX graph, then validate the converted adapter against a Diffusers reference.

    Runtime status

    Inference is not wired up yet

    Target architecture: offline Python/Diffusers conversion, then ONNX Runtime WebGPU inference in this page. Python would be used for export only; no Python inference server is intended. ExecuTorch WebGPU is a second experimental route being evaluated. The FLUX.2 application remains untouched.
